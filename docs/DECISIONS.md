# Decisions
Append-only. To change a decision, add a new entry that supersedes it.

## D-001 · Build Albashi: agency payroll in cNGN, for Stablecoin Corridors + Altana Agent Wallets · 2026-11-21 · accepted
**Context:** "Agents Open for Business" (Celo, Loops House) has four tracks, and a project can win at most two. Stablecoin Corridors and Altana are scored on the same four criteria: execution, value proposition, tagged onchain traction, and a named user with a real job done (25% each).
**Decision:** A payroll agent for a small agency. The client pays the agency in USD₮; the agent converts to cNGN on Textile FX and pays each freelancer, acting from the owner's Altana wallet under a session key (cap, allowlist, expiry, one-transaction revoke). Target user: freelancers and small agencies paid in dollars who want naira.
**Alternatives:** A freelancer's own wallet sweeping income into naira (rejected: every freelancer must set up a wallet before anything counts). A client-side payer abroad (rejected: a foreign client is harder to reach as a named user). Self Agent ID and Agent Vault tracks (skipped: at most two wins count, and Agent Vault is the least tied to Celo).
**Consequences:** Real users are half the score, so a named agency must run a real pay run by M2. Recipients must be able to use cNGN (cash-out path still to be confirmed with a real freelancer).
**Evidence:** internal/research/DOSSIER.md (Decision, sections 5–7); mainnet spike E-001..E-004.

## D-002 · Claim A: "its agent can only pay the payslip you signed" — needs a pay-run contract · 2026-11-21 · accepted
**Context:** Altana's session allowlist is per contract, not per recipient. A session allowed to call cNGN directly could pay anyone within its cap, so "can only pay the people you approved" would be false.
**Decision:** Add a pay-run contract. The owner signs the payslip (recipients, amounts, minimum cNGN-per-USD₮ rate); the contract pays only that list, at that rate or better. The agent's session may call only the pay-run contract and Textile's reactor, never cNGN directly.
**Alternatives:** The narrow claim B ("inside a spending cap you set and can revoke"), which is true with no contract work but restates Altana's own feature and gives a weaker reversal beat.
**Consequences:** About a day of contract work plus tests, in M1. The reversal beat becomes "the agent tries to pay someone not on the payslip, and the contract refuses."
**Evidence:** internal/research/DOSSIER.md (claim break test); the session permission types in `@altananetwork/sdk` 1.1.0 `internal/sessions.d.ts` (`CallPermission` = `{ to }` / `{ signature }`).

## D-003 · Self-relay session intents so the attribution tag sits at the transaction's tail · 2026-11-21 · accepted (revisit if organizers say relayed txs are credited)
**Context:** Through Altana's relay, our tag lands inside the calldata, not at the tail of the outer transaction (E-002, E-003: `verifyTx` returns null). Celo's indexer spec reads the tag only from the tail of the outer `tx.input`, plus ERC-4337 bundles, which Altana's relay isn't. The event also ties the score to one agent wallet.
**Decision:** Albashi's agent EOA submits the session-signed intents to the Orchestrator (`0xaf140d0416a994aebb3fa6212b16ce6700f09751`) itself, with `celo_3f5cac8c49f6` at the tail. That EOA is the event's agent wallet.
**Alternatives:** Ask Altana to write a Schema 2 role tag in its relay (the documented model, but outside our control before the deadline); rely on Altana's relay and hope inner tags are credited (unverified).
**Consequences:** The agent EOA pays gas in CELO. Still to verify: that the SDK returns a signed intent without sending it, and how the intent's relay-payment fields behave when we submit it (M0 self-relay spike).
**Evidence:** Orchestrator source verified on Celo Blockscout (`execute(bytes)` is public, with no caller check); internal/research/raw/attribution-indexers-2026-11-21.md.

## D-004 · One ERC-8004 identity: Albashi's agent EOA, not each customer wallet · 2026-11-21 · accepted
**Context:** `register()` makes `msg.sender` the identity's owner and wallet. Altana registers an identity for every new wallet by default (`agentIdentity`, on by default).
**Decision:** Register Albashi's identity once, from the agent EOA. Create customer wallets with `agentIdentity: false`. Ask owners and freelancers to rate the agent in the Reputation Registry after a pay run.
**Alternatives:** An identity per customer wallet (scatters reputation and activity across many agents).
**Consequences:** One place for all reputation; the registration file lists Albashi's endpoints.
**Evidence:** docs.celo.org/build/agents/8004 (read 2026-11-21); `@altananetwork/sdk` 1.1.0 `client.d.ts` (`CreateClientOptions.agentIdentity`).

## D-006 · Self-relay confirmed on mainnet; owner actions stay on Altana's relay for now · 2026-11-21 · accepted · confirms D-003
**Context:** D-003 depended on an untested recipe.
**Decision:** Albashi's agent self-relays every payout intent (E-005: tag at the tail, `verifyTx` reads it, sent from the agent EOA). The owner's one-off actions (create wallet, grant, revoke) keep going through Altana's relay for now, untagged; revisit if the organizers count owner-side transactions.
**Consequences:** The agent EOA needs a little CELO for gas (~0.08 CELO per payout intent). Each intent still pays Altana's quoted relay fee from the owner wallet (~0.32 CELO ≈ $0.02), on top of our gas. The product code must re-implement the hold-and-submit step cleanly (not a `fetch` interception) and must always simulate first (`execute` returns an error code instead of reverting).
**Evidence:** E-005, E-006, E-007.

**Decision:** The public page is the lock screen a payment lands on: Lagos at dusk, the live Textile USD₮→₦ rate at clock scale with its read time, and frosted SMS-style alerts from sender ALBASHI. ## D-008 · Add an infrastructure layer after the core claim, aimed at Prezenti's Frontier pool · 2026-11-22 · accepted
**Context:** Prezenti's Frontier pool funds "AI and agent economy infrastructure on Celo… that other builders and agents rely on, rather than end-user applications" ($15,000+ USDm, one-off, 20% at onset and 80% on delivery; requires Celo mainnet, real onchain usage, ERC-8004 and Self Agent ID). Albashi's pieces (Textile quoting, receipt parsing, self-relay with tags, the pay-run contract) are reusable by other agents. The user had sketched the same layer before this build (corridor SDK, x402 payout endpoint).
**Decision:** Hackathon core first: the pay-run contract, the owner desk, a real agency pay run. Then, about 2–5 Dec, an infrastructure layer reusing them: a `corridor-sdk` package, an x402-paid payout endpoint whose payouts are held to the pay-run contract's signed-payslip rule, `/.well-known/agent.json`, and ERC-8004 plus Self Agent ID registration. Apply to Frontier after 7 Dec with the usage the hackathon produced. A plain-English input may only draft payslip lines the owner signs (AGENTS.md rule 6). **Consequences:** Registering Self Agent ID (the user agreed, with their own ID, when the agent exists) is not entering Self's prize track; that track stays cut (D-001). x402 settlements are sent by Celo's facilitator and are not tagged yet; our own payouts stay self-relayed and tagged. Prezenti's status ("open to 29 Dec" vs "currently closed") and its grant policies are unverified until the user reads them.
**Evidence:** internal/research/layer1-2026-11-22.md; docs/CONTEXT.md "Agent economy rails" (x402 live config lists USD₮ and cNGN; Self's mainnet registry has code).

## D-009 · PayRun is the session's only target, and the Textile taker · 2026-11-22 · accepted · implements D-002
**Context:** Altana call permissions pin a target and a function selector, never the arguments (`CallPermission` = `{ to, signature }`). A session allowed to call USD₮ or cNGN `approve`/`transfer` could pay anyone; a session allowed to call Textile's reactor directly could fill any order at any price. Textile's `LimitOrderReactor` (verified on Celo) sends an order's input to `msg.sender` and pulls its outputs from `msg.sender`; Textile binds each firm quote to one taker and accepts smart-contract takers through EIP-1271.
**Decision:** The owner's session may call only `PayRun.run`. The owner approves PayRun for USD₮ once, from their own key. A run checks the owner's EIP-712 payslip signature, the deadline, single use and that the caller is the owner; pulls at most the signed USD₮ budget; fills Textile's quote with PayRun as the taker (selectors `execute`/`executeBatch` on the immutable reactor only); measures the cNGN actually received against the signed minimum rate; pays exactly the signed lines; and refunds the rest. `isValidSignature` accepts only Albashi's agent key, for Textile's taker proof. The owner's key is checked by ECDSA before ERC-1271, because an EIP-7702 account is an EOA with code.
**Alternatives:** The swap from the owner's wallet with the reactor on the allowlist (rejected: the rate floor would not bind). Pulling cNGN the owner already holds (deferred: not needed for the claim).
**Consequences:** Textile quotes are requested with `taker = PayRun`; the agent signs the TakerControl proof, valid ~12 h per taker. The owner's one-off USD₮ approval to PayRun is an owner action (Altana relay, untagged). The contract holds nothing between runs. Not audited.
**Evidence:** `contracts/src/PayRun.sol`; `forge test`: 24 tests incl. a 256-run fuzz of the rate floor; mainnet fork checks (CELO_FORK=1): both tokens 6 decimals, the reactor exposes both fill selectors.

## D-010 · PayRun keeps each owner's USD₮ float; the owner funds it with its own tagged transactions · 2026-11-22 · accepted · supersedes D-009 in part, D-006 in part
**Context:** Textile checks proof of funds on every firm quote: the taker must already hold the USD₮ it will pay. PayRun is the taker (D-009), and v1 pulled USD₮ from the owner's wallet inside the run, so Textile refused to quote it (`insufficient_funds`, 2026-11-22). v1 has no withdraw. Separately, the owner key is an EOA with an EIP-7702 delegation and can send its own transactions for gas alone (~0.01 CELO, tagged), where an Altana-relayed owner action costs ~0.3 CELO and is untagged.
**Decision:** PayRun v2 holds a USD₮ float per owner. Only the owner deposits to it (credited by the balance that arrived) or withdraws it, and only a payslip that owner signed spends it. A run reserves at most `usdtIn` (≤ the signed `maxUsdtIn`) from that owner's float before the swap, approves the reactor for exactly that, and credits back what the swap did not spend. The session's only call permission is `PayRun.run`. There is no USD₮ spend cap: a run moves no USD₮ out of the owner's wallet, so one would bind nothing. The money limits are the float the owner chose and each payslip's signed budget, rate floor and deadline. The owner's funding and admin actions (exact approval, deposit, removing stale permissions) are its own transactions, tagged. The session grant stays on Altana's relay (untagged). v1 is retired.
**Alternatives:** A partner API key with the `rfq:aggregator` scope, which skips the funds check (not self-serve). Quoting with the owner's wallet as taker and the swap outside PayRun (rejected in D-009: the rate floor would not bind).
**Consequences:** PayRun now holds owners' USD₮ between runs. It is not audited, and its invariant is that USD₮ held ≥ `totalFloat` (equal after the first run). D-009's "holds nothing between runs" and "owner approves once through Altana" no longer apply, and its "taker proof valid ~12 h" was wrong: Textile rejects a proof minutes after issue, so the agent signs one per quote. Textile also holds the float against open quotes, so the agent asks for a firm quote only when about to run. Re-granting a key adds permissions, so retiring a contract means removing its permission too (done for v1, E-011). One run's relay fee (0.667 CELO) uses most of the SDK's default 1 CELO/day fee cap.
**Evidence:** E-008 to E-011; `contracts/src/PayRun.sol` (33 tests, including the float isolation and the backing invariant).
